Что и как проверялось
Прочитан весь рантайм: include/, src/, fuzz-цели, CMake для фаззинга, CI и список тестов. Бенчмарки не запускались, поэтому все пункты про скорость остаются гипотезами, которые нужно проверять замерами. Остальное проверено по коду.
Новые находки
1. Отключённый wake-protocol фаззер
   Это самая важная находка. Все семь DAGFLOW_FUZZ_POINT в исходниках закомментированы, а в cmake/DagFlowFuzz.cmake слой wake_protocol намеренно запрещён через FATAL_ERROR. Это единственный слой, который возмущает расписание вокруг idle_announce, before_cv, wake_claim и before_retire, то есть самый тонкий протокол рантайма. saturation_fuzz ждёт точку external_retry, которая тоже закомментирована.
   Без hooks макрос превращается в ((void)0), так что на скорость обычных сборок это не влияет. Рекомендация: вернуть точки и включить слой обратно.
2. Реестр продюсеров в IdleAccounting
   • Каждый внешний поток, хоть раз сделавший submit, навсегда остаётся в односвязном списке до смерти пула (примерно 128 байт на поток). Если приложение создаёт много короткоживущих потоков, список растёт, а wait_idle проходит его целиком.
   • TLS-кэш из 4 слотов индексируется как identity_ % 4. Поток, который работает с несколькими пулами, может постоянно вытеснять свой слот. Тогда каждый submit уходит на медленный путь с mutex и линейным поиском по списку.
   Лечится ассоциативным кэшем побольше и освобождением lane при завершении потока.
3. GraphScope::parallel_for по умолчанию последовательный
   Дефолт NodeOptions::concurrency = 1, а lanes = min(tokens, capacity, concurrency). Поэтому parallel_for(begin, end, f) без опций исполняет все токены одним lane. В README это упомянуто (строка 73), но ловушка остаётся. Для узлов с tokens > 1 дефолтом лучше сделать 0 (размер пула).
4. API-ловушки в GraphScope и TaskGraph
   • ~GraphScope запускает ещё не стартовавший граф и молча глотает исключения. Если построение упало на полпути, при раскрутке стека исполнится часть графа.
   • GraphScope::submit() не исполняет задачу, а только создаёт узел, тогда как Pool::submit() исполняет сразу. Одно слово, разное поведение.
   • Синонимов много: emplace, add_node, submit, spawn.
   • TaskGraph::cancel() требует внешней синхронизации с run, reset и clear, хотя отмена нужна именно из другого потока.
   • JobHandle не знает, какому графу принадлежит: хэндл из чужого scope молча привяжется к узлу с тем же индексом.
5. parallel_for в GraphScope
   Выделяет Parts ещё до проверки n == 0. std::next(begin, lo) и std::next(begin, hi) считаются с нуля на каждый чанк, а это O(n·chunks) для forward-итераторов. Тот же приём стоит в Pool::for_each (thread_pool.hpp:246).
6. CI
   Sanitizers и fuzz работают только на ubuntu-24.04 (x86). На ARM (Linux, macOS, Windows) крутится лишь набор core без TSan, а слабые ошибки порядка памяти в Chase–Lev и в fence-протоколе на x86 не проявляются. Рекомендация: добавить check-tsan на ubuntu-24.04-arm. По README, replay fuzz-корпусов тоже идёт не под TSan.
7. small_function и small_vector
   Аккуратный код, замечаний по корректности нет. Мелочь: callable без noexcept-move молча уходит в heap, и это стоит хотя бы посчитать диагностическим счётчиком.
8. Диагностический билд
   Счётчики уже есть: cross_thread_free, packet_allocations, help_attempt, help_success, park_timeout, wake_signal, steal_lost. Прогнать noop и nested_spawn в этом режиме и смотреть дельты, а не гадать. Если cross_thread_free в noop близок к числу задач, значит, аллокатор действительно участвует.
   Из прошлых списков (всё ещё актуально)
   Корректность и поведение
   • Помощь при Pool::wait на воркере: заменить yield-спин на парковку с пробуждением по новой задаче и по готовности handle.
   • Глубина стека при вложенном helping не ограничена.
   • pin_threads = true по умолчанию, без учёта cpuset, SMT и processor groups: поставить false.
   • Простаивающие воркеры просыпаются до каждых 200 мкс (idle_us_max = 200).
   • Исключения из submit_detached молча теряются: нужен обработчик или политика.
   • Блокирующие задачи не компенсируются.
   Производительность (замерять)
   • Прогнать noop с mimalloc и tbbmalloc до любых изменений в аллокации.
   • Координация внешнего submit: два RMW на admission_, общий fetch_add в select_shard, fence в wake_one.
   • Облегчить CompletionState: mutex, vector и exception_ptr вынести в ленивый блок.
   • Внешний продюсер при полной очереди крутится в yield.
   • Overflow-очередь на mutex проверить сценарием fan-out больше 1024.
   Документация и репозиторий
   • Строка «Independent tasks» в README меряет payload, а не рантайм. Указать аллокатор рядом с цифрами.
   • Добавить доверительные интервалы для основных замеров.
   • Дубли lifetime-invariants-*.md, пустой noop_fix.md, smth_useful.md, .patch и сырые JSON вынести из репозитория.
   • CMake-инфраструктура (259 КБ) больше самого рантайма (163 КБ).
   • Вводящий в заблуждение отступ в Scheduler::steal (return tasks[0]).
